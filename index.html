Object Detection Performance Evaluation in Weather Conditions Using CarMaker

Automated synthetic dataset collection and YOLOv8m robustness evaluation under adverse weather conditions using CarMaker RSDA API and CUDA nvJPEG acceleration.

2026.01 - 2026.02

Key Contributions

  • Parameterized adverse weather variables (Sun, Cloud, Rain, Snow, Fog) across 2 driving tracks to construct 4 distinct scenario datasets totaling 6,228 synthetic frames.
  • Developed a high-speed GPU image capture plugin (`JpegEncoder.cu`) binding Movie NX RSDA API with CUDA `nvjpeg` library for real-time 1280x800 JPEG compression.
  • Built a C++ Ground Truth Auto-Labeling pipeline (`GTLabelWriter.cpp`) using 3D-to-2D pinhole camera projection to generate pixel-accurate 2D YOLO annotations.
  • Designed an absolute simulation time indexing algorithm based on `SimCore.Time` to eliminate timing offsets between physics updates and image capture routines.
  • Executed YOLOv8m fine-tuning and conducted comprehensive quantitative (mAP@0.5, PR Curve, Confusion Matrix) and qualitative evaluations against pretrained baselines.

Engineering Growth & Learnings

  • Mastered 3D-to-2D pinhole camera projection geometry, transformation matrices from CarMaker Sensor Frame (FrS) to pixel space, and normalized AABB calculations.
  • Gained hands-on experience with CUDA memory management (`cudaMalloc`, `cudaMemcpy`) and `nvjpeg` parameter tuning to prevent I/O bottlenecks during high-throughput vision data logging.
  • Enhanced problem-solving skills regarding simulation lifecycles, real-time physics engines, and absolute timestamp synchronization.
  • Acquired deep expertise in quantitatively evaluating autonomous vision AI performance degradation under adverse weather conditions (rain, snow, fog).

Problem Setting & Solution

  • Manual Annotation Bottlenecks: Replaced manual labeling (~1,800 frames) with a C++ GT Auto-Labeling pipeline inside `User_Calc` to achieve 100% automated, pixel-accurate 2D annotations.
  • Simulation I/O Latency: Bound Movie NX RSDA API with CUDA `nvjpeg` to compress RGB buffers directly in GPU memory before disk saving, mitigating CPU overhead and simulation lag.
  • Label-Image Frame Offset: Resolved a non-detection bug (1.00 Background Miss on Traffic Lights) by implementing absolute time indexing (`elapsed / 0.060`) with a -1 frame offset correction.

Key Results & Metrics

  • 100% Data Automation: Automated the E2E synthetic data collection pipeline, generating 6,228 high-resolution image-label pairs across 4 weather scenarios.
  • 88% Accuracy Restored: Restored traffic light detection accuracy from 0% to 88% by correcting the physical update-to-capture timing offset.
  • mAP@0.5 = 0.583: Achieved strong fine-tuned YOLOv8m performance across all classes (`car`: 0.892, `truck`: 0.696, `person`: 0.686) while eliminating false positives from falling snow.

Blind Spot Accident Prevention System (BSAPS)

Real-time Alert System for Blind Spots: Implemented immediate warning signal control logic using the STM32 board to prevent accidents on narrow blind-spot roads.

2025.06 - 2025.08 (Lead Embedded Developer / STM32 Nucleo-F401RE Control & Signal Processing)
Click to Expand Diagram

Key Contributions

  • Designed and implemented a high-performance hardware-accelerated rendering engine using TIM1 synchronization and DMA2 transfers.
  • Engineered a double-buffering scheme (LED_MEM0, LED_MEM1) with VSYNC interrupt flags (led_dma_take_vsync) to eliminate screen tearing.
  • Built an offline BSRR word-stream pre-compiler (build_from_pixel_fn) to package RGB bitplanes, CLK, LAT, and OE signals into pre-computed 32-bit DMA command streams.
  • Restructured hardware architecture by remapping all control/data lines to a single GPIO port (GPIOB) to satisfy single-address DMA register constraints.

Engineering Growth & Learnings

  • Gained deep expertise in microcontroller peripheral synchronization (DMA, TIM1, GPIO BSRR registers) and asynchronous interrupt-driven architectures.
  • Mastered memory vs. execution trade-off management when transitioning from CPU-driven bit-banging to memory-heavy pre-compiled command buffers.
  • Learned advanced temporal color modulation techniques, including 5-bit color bitplane decomposition and gamma correction mapping.

Problem Setting & Solution

  • Single-Port Register Constraint: Resolved multiline GPIO port distribution by re-wiring all HUB75 pins (Address A–D, RGB1/2, CLK, LAT, OE) to GPIOB so DMA could execute single-address transfers directly to the GPIOB BSRR register.
  • CPU Overhead Bottleneck: Shifted rendering paradigm from runtime pixel polling to pre-building 32-bit control word streams (fb0, fb1), completely offloading the display refresh rate workload from the CPU to DMA2.
  • Display Tearing & Synchronization: Implemented non-blocking double-buffering using HAL_DMAEx_MultiBufferStart_IT combined with an asynchronous main loop event check (led_dma_is_mem_free) to prevent writing during active DMA transfers.
  • Temporal Brightness Control: Developed a 5-bit depth bitplane splitting algorithm (u8_to_plane, cw_from_bits) paired with TIM1 timing intervals to maintain steady gray-scale rendering without flicker.

Key Results & Metrics

  • 0% CPU Utilization for display refresh operations, leaving CPU fully available for RTC time processing and real-time animations.
  • Flicker-Free Performance Stable frame rate delivered via DMA-driven BSRR streaming synced to TIM1.
  • 100% Tearing Elimination: Completely smooth buffer swapping achieved through VSYNC-aligned asynchronous double buffering.

Key Contributions

  • Built a multi-threaded Linux C socket server architecture using `pthread_create()` and `pthread_detach()` for asynchronous, concurrent client command processing[cite: 10, 11].
  • Implemented a plugin-based hardware control driver layer via dynamic shared libraries (`.so`) loaded at runtime using `dlopen()` and `dlsym()`[cite: 10, 11].
  • Designed multi-level LED brightness control (`softPwm`) and music playback engine (`softTone`) integrated with CDS light sensors and 7-segment displays[cite: 10, 11, 13, 15, 17].
  • Architected a robust Linux background daemon process featuring double `fork()`, `setsid()`, log redirection (`dup2`), and clean `SIGINT` signal handling[cite: 10, 11].

Engineering Growth & Learnings

  • Mastered Linux daemonization mechanics, process group session isolation (`setsid`), and standard stream redirection for background logging[cite: 10].
  • Deepened understanding of C shared library runtime symbol resolving, function pointer casting, and dynamic memory safety (`dlclose`)[cite: 10].
  • Acquired expertise in line-buffered I/O streams (`_IOLBF`) and thread-safe file descriptor management across fork boundaries[cite: 10].
  • Gained practical knowledge in software PWM timing constraints and the impact of repeated GPIO initialization on kernel/library state[cite: 10, 14, 17].

Problem Setting & Solution

  • Daemon Log Interception Loss: Standard I/O streams were lost post-`daemonize()`; resolved by redirecting `STDOUT` and `STDERR` to `server.log` using `dup2()` with line-buffering[cite: 10].
  • PWM Timer Segment Failure: Repeated `wiringPiSetupGpio()` calls inside dynamically loaded modules crashed SoftPWM; fixed by centralizing setup to a single startup call (`device_init()`)[cite: 10, 14, 17].
  • Port Rebind Failures on Shutdown: Abrupt daemon terminations caused socket port locks; solved by registering a `SIGINT` handler to explicitly `close(server_fd)`[cite: 10].

Key Results & Metrics

  • 0% Command Corruption: Achieved flawless execution across concurrent client commands through thread-safe socket dispatching[cite: 10, 11].
  • Zero Downtime Upgrades: Enabled real-time hot-swapping and addition of hardware control modules without restarting the core TCP server[cite: 10, 11].
  • Sub-ms Command Responsiveness: Delivered real-time sub-millisecond control across 4-level LED PWM, melody playback, and sensor monitoring[cite: 10, 11, 17].
